# Updating kde.nix

`kde.nix` declares KDE Plasma settings (shortcuts, theme, Night Color, etc.)
via [Home Manager](https://github.com/nix-community/home-manager) +
[plasma-manager](https://github.com/nix-community/plasma-manager). This
document explains how to refresh it from a live system.

## How it gets applied

`kde.nix` stays wired into `configuration.nix`'s `imports` permanently —
`configurations.sh` adds it at install time and never removes it. Every
`sudo nixos-rebuild switch` re-applies it, including plain NixOS options
declared at the top level (like `environment.sessionVariables`) and the
Home Manager/plasma-manager block under `home-manager.users.leans`.

This means changes made by hand in System Settings for anything also
declared in `kde.nix` (shortcuts, `configFile` entries, etc.) get reverted
back to the file's values on the next rebuild. If you want a System
Settings tweak to stick, run `update-kde-nix.sh` (see below) to bake it
in.

## Capturing your current KDE settings (automated)

1. Change whatever you want in KDE System Settings on a system that's
   currently running it — theme, shortcuts, Night Color, touchpad
   settings, anything. There's no "personal taste" category to leave out
   anymore: whatever you set live is what gets baked in.
2. From the repo root, run:
   ```
   ./update-kde-nix.sh
   ```
   This dumps your current config with `rc2nix`, strips the stuff listed
   under "What always gets left out" below, and rewrites the
   `shortcuts`/`configFile` blocks in `kde.nix` in place. It validates
   the result with `nix-instantiate --parse` and restores the original
   file if anything goes wrong.
3. Review `git diff etc/nixos/kde.nix` before committing.
4. Rebuild: `sudo nixos-rebuild switch`

## Capturing your current KDE settings (manual)

If you'd rather do it by hand (e.g. to only grab a couple of settings):

```
nix --extra-experimental-features "nix-command flakes" run \
  github:nix-community/plasma-manager#rc2nix > kde-dump.nix
```

Then copy the attributes you care about from `kde-dump.nix` into the
`programs.plasma = { ... }` block in `kde.nix` — `shortcuts`,
`configFile`, etc. — applying the same exclusions as the script (below)
by hand.

## What always gets left out

- **Session/UI state**, not preferences — e.g. `dataFile."kate/anonymous.katesession".*`
  (which files were open in Kate, window splitter positions). This is
  regenerated by the app every time, not something you configure.
  `update-kde-nix.sh` never touches `dataFile` at all.
- **Hardware-specific entries** — anything under
  `kcminputrc."Libinput/<vendorId>/<productId>/<device name>"` only
  applies to that exact mouse/touchpad model. If you want a setting (like
  "no pointer acceleration") to apply no matter which device is plugged
  in, that belongs in `configuration.nix` instead, via
  `services.libinput.mouse.accelProfile` — a NixOS-level default, not a
  per-device KDE one. Note this only covers X11 sessions; KWin Wayland
  has no generic equivalent and needs a per-device entry under
  `programs.plasma.input.mice` if you need it there too.
- **Random per-install IDs** — e.g. `kwinrc."Tiling/<uuid>/...".*` or
  activity UUIDs tied to one specific machine's state.

## Known limitation: panels and widgets

`rc2nix` does **not** capture panel/widget layout
(`plasma-org.kde.plasma.desktop-appletsrc`) — that file's format isn't
reliably convertible to plasma-manager's declarative `panels` syntax. If
you want panel layout reproduced too, write it by hand under
`programs.plasma.panels = [ ... ];` (see the example in `kde.nix` and the
[plasma-manager
README](https://github.com/nix-community/plasma-manager#panels) for the
syntax).

## After editing

Validate the Nix syntax before committing:
```
nix-instantiate --parse etc/nixos/kde.nix
```
